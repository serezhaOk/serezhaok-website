# serezhaok.com

Портфолио Сергея Дюжева, перенесённое с Framer в собственный код: Next.js 15 (статический экспорт), TypeScript, анимации на `motion`, хостинг GitHub Pages. Бэкенда, CMS и базы нет — весь контент лежит в репозитории.

## Запуск

```bash
npm ci
npm run dev        # http://localhost:3000
npm run build      # статический сайт в out/
npm start          # посмотреть собранный out/
npm run typecheck
```

Нужен Node 22.

## Как добавить или поменять кейс

Каждый кейс — один файл в `content/projects/`. Вёрстку трогать не нужно.

1. Положите картинки и видео в `public/media/<slug>/` (например, `01.png`, `02.mp4`). Для видео рядом положите постер с тем же именем и расширением `.jpg` — он показывается, пока видео грузится.
2. Скопируйте любой файл кейса, например `content/projects/musescore.ts`, в `content/projects/<slug>.ts` и поменяйте тексты.
3. Добавьте кейс в массив в `content/projects/index.ts`.
4. Если кейс должен быть в меню Projects или на главной — добавьте его в `menu` и `homeCards` в `content/site.ts`.

Адрес страницы будет `/<slug>/`.

### Блоки контента

```ts
{ type: 'h2', text: 'Observation' }              // заголовок секции
{ type: 'h3', text: 'Impact' }                   // крупный подзаголовок
{ type: 'label', text: 'The Problem' }           // мелкий серый подзаголовок
{ type: 'p', text: 'Текст с **жирным**, *курсивом* и [ссылкой](https://…)' }
{ type: 'list', items: ['пункт', 'пункт'] }
{ type: 'divider' }                              // линия между крупными секциями
{ type: 'media', items: [m('/media/slug/01.png', 3200, 3200)] }              // на всю ширину
{ type: 'media', cols: 2, items: [m(...), m(...)] }                          // два в ряд
```

### Точная подгонка под оригинал

В Framer каждая секция свёрстана вручную, поэтому местами отступы и размеры отличаются от общих правил. Такие места подогнаны необязательными полями блока — в новых кейсах они не нужны:

```ts
{ type: 'p', text: '…', mt: [10, 10] }        // отступ сверху, px: [десктоп, планшет и телефон]
{ type: 'p', text: '…', maxWidth: '80%' }     // ширина на десктопе: '80%' от колонки или 840 (px)
{ type: 'p', text: '…', mobileText: [20, 24] } // кегль и интерлиньяж на планшете и телефоне
```

У медиа есть `h: [600, 300]` — фиксированная высота вместо пропорций. У кейса — `headerSpace`, `endSpace` и `largeMobileHeadings` (см. `content/types.ts`). Значения вписаны скриптом по замерам serezhaok.com, а не на глаз.

`m(src, ширина, высота, рамка?)` — ширина и высота файла нужны, чтобы страница не прыгала при загрузке. Необязательная `рамка` — пропорции, в которые обрезается медиа (например, `1.2` для 6:5 или `1` для квадрата). На планшете и телефоне ряды складываются в колонку; чтобы оставить два в ряд, добавьте `mobileCols: 2`.

## Медиа

Все файлы лежат в `public/media/`. Оригиналы с Framer скачаны один раз скриптом:

```bash
npm run fetch-media   # докачивает недостающее по scripts/media-manifest.json
```

После скачивания у видео убрана звуковая дорожка, `musescore/10.mp4` пережат (был 22 МБ), для всех видео сделаны постеры `.jpg`. PNG не конвертировались: Framer отдаёт их уже сжатыми, самый тяжёлый — 1,6 МБ.

Ссылок на framerusercontent.com в коде сайта нет — после отключения Framer сайт продолжит работать.

**Заглушка:** `public/media/menu/collabs.png` (превью Collaborations в меню) вырезан из записи экрана — оригинала на живом сайте нет. Замените, когда будет исходник.

## Деплой

Каждый пуш в `main` собирает сайт и публикует его на GitHub Pages (`.github/workflows/deploy.yml`). Домен задан в `public/CNAME`.

Один раз вручную (делает владелец репозитория):

1. Settings → Pages → Source: **GitHub Actions**.
2. Settings → Pages → Custom domain: `serezhaok.com`, включить **Enforce HTTPS**.
3. У регистратора домена: 4 A-записи на `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` и CNAME `www` → `serezhaok.github.io`.
4. Отключать Framer только после того, как новый сайт открылся по домену.

## Шрифты

- UI (шапка, меню, тексты кейсов) — Inter, как в оригинале (`@fontsource-variable/inter`).
- Крупные заголовки и тексты на главной — **Tomato Grotesk**, как в оригинале. Это коммерческий шрифт; файл `public/fonts/tomato-grotesk-medium.woff2` взят с serezhaok.com, куда его загрузил заказчик. Если репозиторий публичный, файл может скачать кто угодно — права на его использование на стороне заказчика. Запасной шрифт — Instrument Sans.

## Расхождения со спецификацией

По правилу «если замер расходится с живым serezhaok.com — прав живой сайт» всё сверено с оригиналом в Chromium на ширинах 390, 810, 1199, 1200, 1440 и 1920 px. Отличия от спецификации:

- **Брейкпоинты.** У оригинала их два: от 1200 px — десктоп, ниже — одна колонка с полями 16 px. На планшете и телефоне капсула About me / Projects стоит внизу экрана, имя — сверху без аватара, подпись слева скрыта, карточки Prototypes нет.
- **Сетка.** Левое поле колонки — `82px + 16.875vw` (325 px при 1440, 406 при 1920), правое — 80 px.
- **Шрифты и размеры** сняты из вычисленных стилей: интро 32/44.8, заголовок «Projects» и H1 кейса 75/90, H2 40/48, текст кейса 20/28 (Inter), пункты меню Inter 24/500 и т. д.
- **Меню Projects** на живом сайте открывается по клику (а не по наведению) и закрывается, когда курсор уходит. Панель 443×267, `rgba(240,240,240,.7)` + `blur(13px)`, отступ 6 px под капсулой. Превью: MuseScore — круг 149, Raiffeisen — 149×149 со скруглением 2 px, Muse Group — 149×156, Collaborations — 149×94. Подсветка пунктов появляется и гаснет примерно за 100–120 мс, текст сдвигается на 8 px.
- **Капсула** при наведении не увеличивается: ползунок становится выше (36 → 40 px) и получает тень.
- **Превью Collaborations в меню.** Сейчас на живом сайте у Muse Group и Collaborations одна и та же картинка с телефонами. Оставлен вариант с видео: у Collaborations — скриншот Ori Scan.
- **/collabs.** Медиа нашлись на живой странице — заглушки не нужны. H1 — «Collaborations».
- **Текстовые ссылки и выделение,** которых не было в спеке: Design Studio и COLLINS — ссылки, «3 taps», «~19 seconds», «7.2%» и «Expansive, Charged, and Attuned» — жирные, «reduced stress…» — курсив.
- **«Let's talk»** в оригинале с прямым апострофом и цветом #333; кегль подстраивается под ширину колонки.
- **Мобильная мета кейса** — 2×2 (в оригинале 4 колонки налезают друг на друга на 390 px).
- Нестандартные отступы, ширины и мобильные кегли оригинала перенесены полями `mt`, `maxWidth`, `mobileText` (см. «Точная подгонка»).

### Итог сверки

Каждый текстовый элемент, картинка и видео сопоставлены с оригиналом на ширинах 1920, 1440 и 390 px. При 1440 у главной, MuseScore и Raiffeisen 98–99% элементов стоят в пределах 1–2 px от оригинала, у Muse Group и Collaborations 92–98% — в пределах 4 px. Высота страниц на десктопе отличается на 1–12 px. На телефоне промежутки между блоками перенесены, но Raiffeisen длиннее на ~60 px (в списках оригинала другие отступы). Также на телефоне сознательно не повторены два бага оригинала на MuseScore — мета в 4 колонки, где текст налезает друг на друга, и пара видео+картинка шириной 840 px, вылезающая за экран. Поэтому мобильный MuseScore короче оригинала на ~600 px.
